# Edge MCP + Separate AI Agent Simulator

This solution has two separate C# applications:

```text
EdgebasedMCP       = simulated edge device + local MCP server
AiAgentSimulator  = separate AI-agent-style client that connects to MCP over HTTP
```

This matches the architecture:

```text
Edge Device + MCP Server  <--- HTTP/MCP request-response --->  AI Agent
```

The edge device publishes timestamped latency samples. Each sample contains only a sequence number and the time it was sent.

## 1. Start The Edge/MCP Side First

In PowerShell:

```powershell
cd C:\Users\posti\source\repos\EdgebasedMCP
dotnet run --project .\EdgebasedMCP\EdgebasedMCP.csproj
```

You should see:

```text
info: Startup[0]
      Simulated edge device is starting.
info: EdgebasedMCP.Services.EdgeTelemetryPublisher[0]
      [EDGE -> MCP] seq=1 sentAtUtc=... sentAtUnixMs=...
```

The same operational messages are also written to:

```text
EdgebasedMCP/logs/edgebasedmcp.log
```

Leave this running.

## 2. Start The AI Agent Side Second

Open a second PowerShell window:

```powershell
cd C:\Users\posti\source\repos\EdgebasedMCP
dotnet run --project .\AiAgentSimulator\AiAgentSimulator.csproj
```

You should see:

```text
AI agent simulator is starting.
MCP server URL: http://localhost:5050/mcp
The agent will request latency samples every 15 seconds.

[AI -> MCP] requesting get_latency_sample
[MCP -> AI] seq=2 sentAtUtc=... edgeToAiLatencyMs=1234 requestRoundTripMs=12.3
```

The same operational messages are also written to:

```text
logs/ai-agent-simulator.log
```

This proves the AI-agent side can receive latency samples from the edge/MCP side.

## What To Watch

In the edge/MCP window:

```text
[EDGE -> MCP] seq=3 ...
[MCP -> AI] served tool seq=3 ...
```

In the AI-agent window:

```text
[AI -> MCP] requesting get_latency_sample
[MCP -> AI] seq=3 ...
```

If the `seq` number appears on both sides, the latency sample was generated by the edge device, stored in MCP, requested by the AI agent, and received by the AI agent.

## File Logging

File logging is enabled in each `appsettings.json` file:

```json
{
  "FileLogging": {
    "Enabled": true,
    "Path": "logs/edgebasedmcp.log",
    "MinimumLevel": "Information",
    "IncludeFrameworkLogs": false
  }
}
```

Change `Path` to put the log somewhere else, set `Enabled` to `false` to turn file logging off, or set `IncludeFrameworkLogs` to `true` if you also want ASP.NET/host framework messages in the file.

2. Choose `Configure Startup Projects`.
3. Select `Multiple startup projects`.
4. Set `EdgebasedMCP` to `Start`.
5. Set `AiAgentSimulator` to `Start`.
6. Start debugging.

## Running On Different Machines

If the AI agent is on another machine, the edge/MCP app must listen on a network-accessible address.

On the edge machine, update `EdgebasedMCP/appsettings.json`:

```json
{
  "Urls": "http://0.0.0.0:5050",
  "McpServer": {
    "EndpointUrl": "http://EDGE_MACHINE_IP:5050/mcp"
  }
}
```

Find the edge machine IP address, for example:

```powershell
ipconfig
```

Then on the AI-agent machine, update `AiAgentSimulator/appsettings.json`:

```json
{
  "AiAgent": {
    "McpServerUrl": "http://EDGE_MACHINE_IP:5050/mcp"
  }
}
```

You may need to allow port `5050` through the edge machine firewall.

## Important Files

- `EdgebasedMCP/Program.cs`: application composition and dependency registration.
- `EdgebasedMCP/Controllers`: controller-based HTTP and MCP endpoints.
- `EdgebasedMCP/Services`: edge telemetry, MCP handling, and hosted publishing services.
- `EdgebasedMCP/Options`: configuration-bound option classes.
- `AiAgentSimulator/Program.cs`: simulator host composition and dependency registration.
- `AiAgentSimulator/Services`: MCP client and hosted polling service.
- `AiAgentSimulator/Options`: configuration-bound simulator options.
- `EdgebasedMCP/EdgebasedMCP.http`: manual MCP test requests.
